# 文本写作的重点边界

## 整篇推进与标题归属

文章按读者要理解的整体问题组织，不照搬素材出现顺序，也不逐个回答所有相关问题。每节应推进一部分理解，让读者知道为什么接着读下一节；不能仅因段落各自通顺就判定结构清楚。

同级标题承担可辨认的并列或递进关系，子标题展开父标题承诺的范围。阶段、选择依据、横向约束和未决事项各有职责，不因话题相关就塞在同一父题下。先调整内容归属，再决定标题与层级；统一成“为什么……”或只改标题级别不能修复关系。

按段落在论述中的作用安排归属，不只按共同话题归类。同一对象可以出现在多节，但各处应承担明确的解释任务；归属混杂时先移动、拆分或合并，不以删去实质内容换取顺畅。

一个论点有主要展开位置。概览可以预告，后文可以回扣，但应有不同作用，不在开头、各章和结尾反复重启同一论证。切换观察角度时交代它如何接续前文；材料没有给出的因果、先后或共识不补造，未决问题不写成结论。

FAQ、查询手册或本就独立的会议议题可以按条目组织，不强拉成单一故事。判断依据是读者需要连续理解还是独立查阅，不是否使用问句标题。

## 会话与阅读困难

先回答这一轮的问题，沿用已建立的名称和结论。局部追问不重发整份报告，也不每轮要求选择、批准或行动。用户说难读时，调整内容与解释顺序，不默认降低专业程度，更不推断诊断。

避免只把“决策连续性、偏移处置”拆成短句。双方已在讨论设计流程时，可直接说明：“决定仍记入现有文档；代码与设计不一致时，查清原因再决定改哪边。”说明来自当前事实，不另添机制。

会话解释保存为文档时补齐脱离对话所需的背景和来源；日常答疑不自动创建文件。主阅读路径保留必要原因与条件，不用术语摘要或链接把理解工作推给读者。

## 直接陈述边界，清除防御性套话

主文件的主张保真规则不等于禁用否定句。按语境区分：

| 应改 | 有据时怎样写 |
|---|---|
| 例子只用于帮助理解，却批评它“不能证明普遍规律” | 例子确实被用于过度概括时，指出越界结论 |
| 汇总实验结果时擅自新增统一审计，并把摘要与 CI 一概降格为“只帮助定位” | 任务要求审计时核对具体材料；版本错配只指出对应的证据缺口 |
| 设计方法后例行追加“别套 base/head、别因缺 benchmark 判错”，没有相关误解语境 | 评审确实作了这些判断时，回应其具体依据 |
| 凭空纠正“有人认为获批就已上线” | 发布页混排两种状态，澄清会影响使用判断 |
| 把已知结果改成“这不能说明……仍需验证” | 直接保留结果、未测范围与已有验证安排 |

判断对象是新增立场或偏离的问题，不是否定词数量。逐字引语与有意的文学对比不按普通说明句改写。

## 正文、改写与文体

- 保留主题的研究方法、修复原因和决定依据；删去的是“为了使本文清晰”等写作自述。不要把编辑材料藏进脚注或 HTML 注释。
- 只要求润色时，不擅删作者结论；获准删除某项主张后，也不另添因果质疑和验证要求。歧义指代指出缺口，不借改代词选择未提供的机制。
- 报告按给定材料写，不从技能案例移植结论。描述性报告可以停在结果；研究摘要保留影响解释的条件与负面结果，不写提示中的防错禁令。
- 不强制所有文体结论先行、每段加标题、每章配总结。论文组织服从学科和题目，叙事保留声音、悬念与节奏，操作警告仍在危险动作前。

## 路径、标题与阅读入口

按读者任务和维护边界组织，不照搬源码树，也不为套文档分类创建空目录。多个入口链接同一权威内容，不复制整套正文。

名称在实际导航语境中足够辨识即可；保留机器约定的文件名、已有版本边界及 URL/锚点兼容要求。标题准确承诺内容，不能靠更长标题掩盖混杂任务，或为标题对称补造内容。连续正文无需给每段贴“提出问题”等编辑标签。
