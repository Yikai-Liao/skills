# 长篇组织与持续写作

长篇的理解成本来自跨章依赖、重复、覆盖缺口和观点漂移，不能只靠逐句润色解决。

## 全局结构

先固定作品的读者、阅读承诺、范围与主线，再为章节建立轻量地图：

| 章节 | 回答的问题或叙事作用 | 必要前置 | 新增内容 | 通往哪里 |
|---|---|---|---|---|

章节地图留在写作笔记中；正文不输出“本章职责”“新增内容”“这样安排的理由”等编辑字段或其改写。检查：

- 每章是否推进作品，而非换词复述前章；必须覆盖的问题是否有归属。
- 平行章节是否采用可解释的组织尺度，分类标准有没有中途变化。序言、方法、附录等不同角色可以采用不同结构。
- 核心概念是否在使用前引入；必要的延后解释是否有简短定义与准确路标。
- 结论是否在正文有依据；后半本书是否突然依赖前面没有建立的概念或假设。

教科书可按知识依赖递进；手册按查询入口组织；叙事作品可以倒叙与延迟揭示。不要用一条“结论先行”抹平差异。

## 分层而不割裂

- 在首次必要使用处给出足够定义；深推导可以后置，但不能只写“详见后文”而让当前论证无法理解。
- 概念有唯一权威定义，跨章使用稳定名称和直接引用。允许为独立阅读补一个简短回顾，不复制整章。
- 长报告的摘要、正文和附录可服务不同读者。关键不确定性与适用条件必须随摘要结论一起出现。
- 图、表、例子和练习要承担明确的解释任务。图文的单位、符号、编号与结论保持一致。

### 多入口手册：按读者任务分层

Django 5.2 文档为首次学习、理解概念、查询接口和解决具体问题提供不同入口。观察这种组织时，检查入口是否对应真实任务，而不是只学习四个栏目名称。

反例目录（教学改写）：安装 → API 参数大全 → 第一个应用 → 部署步骤 → 模型原理。第一次做应用的读者被参数表打断，查接口的人又要穿过教程；章节有标题，但阅读路径混杂。

正例组织：

| 读者当前要做什么 | 对应入口 | 入口承担的工作 |
|---|---|---|
| 第一次做出应用 | 教程 | 按依赖顺序完成有反馈的步骤 |
| 理解模型等核心概念 | 主题指南 | 建立关系、解释机制与背景 |
| 查询 `QuerySet.get()` 的异常 | API 参考 | 直接找到调用条件与结果 |
| 已有基础，准备部署 | 操作指南 | 完成特定任务所需的步骤 |

同一主题可以从不同入口到达，不必复制整套定义。查询页保留当前任务必需的契约；深入机制可链接到主题指南，不能只让读者回头重读教程。单一用途的小手册无需凑齐四类栏目。

### 长报告摘要：比较基线随结论保留

任务是从气候报告摘要判断温度变化的时间范围与比较对象。

反例压缩：“全球地表温度已上升约 1.1°C。”数值还在，读者却不知道相对哪个时期、在哪个时期观测，也可能将长期平均变化误读为某一年的变化。

正例，保留 IPCC AR6 综合报告摘要中的这项温度结论：

> 2011—2020 年的全球地表温度比 1850—1900 年高约 1.1°C。

详细分区估计和方法可以放在下层；对象、观测时期、基线与单位直接决定这项结论的含义，不能一起移走。这不要求每个摘要复述全部数据，也不允许把其他结论的关键不确定性隐藏到附录。

## 持久化最少必要状态

跨会话或分批写作时，优先复用项目现有目录；没有约定时可用 `writing-notes.md` 记录：

1. 读者、目的、体裁、交付语言、作者声音和授权范围；
2. 章节地图、完成状态和稿件路径；
3. 核心术语、定义位置、重要主张及来源；
4. 必须保留的数字、条件、叙事事实或代码契约；
5. 未解决问题、已作决定、待检查交叉引用及下一步。

有大量来源时可另存来源清单；复杂术语体系再单独建词表。不要预先创建一整套没有使用者的工作区。

恢复时先读状态、当前稿与相关依赖，再续写。以文件中的当前版本为准，不凭聊天摘要重造已定结构。

## 分批交付

整本书超出一次合理交付规模时，确定章节顺序与本批范围，先交付有实质内容的章节。不要把大纲、占位标题和“此处展开”累计成完稿页数。

每批检查本章语义与阅读路径，再检查与相邻章节的入口、术语、编号和主张是否一致。记录哪些章节未读，抽样审查不能宣称全书通过。

全稿完成时做三遍检查：

1. **主线遍**：只读目录、章首章末与摘要，能否重建一致的结构和结论。
2. **依赖遍**：追踪核心术语、前提、图表、引用及关键论点在全稿中的使用。
3. **读者遍**：连续读一个代表性章节，并从非线性入口查找一个真实问题，检查两种阅读方式。

无法取得全稿时，不声称完成全局修订。在交付说明中列出尚需核对的具体文件或章节，不把覆盖状态或自检说明写进章节正文。
