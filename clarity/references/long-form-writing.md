# 长篇组织与内容衔接

长篇重点处理跨章依赖、重复、覆盖缺口与观点漂移。

## 组织全书

围绕读者、范围与主线安排章节：每章回答什么，依赖哪些前文，新增什么，又引向哪里。这些关系用于组织内容，不是必填工作表或正文标签。

检查问题是否有归属、结论是否有依据、概念是否及时引入。同级章节保持可解释的分类尺度；序言、方法、附录等不同角色不强求同构。教程可按知识依赖，手册按查询入口，叙事允许倒叙与延迟揭示。

## 分层而不割裂

首次必要使用处给足定义；深推导可后置，但“详见后文”不能让当前论证悬空。定义有权威位置，跨章用稳定名称与准确引用；独立阅读所需的短回顾可以保留。

摘要保留影响判断的时间、对象、基线、条件与负面结果；图表、例子和练习各有解释作用，单位、符号、编号和结论一致。

**多入口手册：** Django 5.2 为首次做应用、理解概念、查接口和完成操作分别提供教程、主题指南、API 参考和操作指南。将“安装 → API 参数大全 → 第一个应用 → 部署 → 模型原理”混成一路，会同时妨碍学习与查询。查询页保留所需契约，再链接深入解释；单用途手册无需凑齐四类栏目，也不为多入口复制定义。

**摘要保留基线：** “全球地表温度上升约 1.1°C”缺少时间与比较对象。IPCC AR6 综合报告的相关结论可摘述为：

> 2011—2020 年的全球地表温度比 1850—1900 年高约 1.1°C。

分区估计和方法可以下移，这句话中的时期、基线与单位直接决定含义。

## 跨章与续写

沿用读者定位、语言、视角、作者声音、术语、编号及人物事实；有意转换时给出可辨识的语境。新章推进新内容，承接已有概念，不换词重写前章。大纲、正文和续写状态各归其位，章节中不混进度流水。
