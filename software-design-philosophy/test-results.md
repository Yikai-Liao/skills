## 最终结论

- 当前 `test-prompts.json`：33/33 通过。
- 最终有效盲测：50/50 通过。
- 元数据触发：20/20 通过，7 个不应触发场景零误触。
- 11 个方法 reference 均被至少一个正例正确选为唯一主路由。

## 盲测方法

测试由三个首次接触合并技能的独立 agent 和一个修订后复测 agent 完成。

1. **元数据触发测试**：只提供 `name`、`description` 和匿名请求，不提供技能正文、题型或预期答案。
2. **reference 路由测试**：只提供技能目录和匿名请求，允许按技能指示读取所需 reference；不提供预期主路由、第一动作或评分规则。
3. **修订复测**：发现一个真实歧义后修改根 `SKILL.md`，再由新的独立 agent 测试失败场景及其两侧边界。
4. `test-prompts.json` 与本文件均在盲测完成后创建，盲测 agent 无法从仓库读取答案。

## 失败与修订

初测 B10：

> 上层要求直接拿数据库事务对象，说这样才够快；目前没有 profile，也没检查通用接口是否漏了原语。

盲测 agent 将 `design-measured-critical-paths.md` 选为主 reference。虽然它拒绝直接批准穿透，但第一步仍是建立性能基线，不符合用户裁决的顺序：出现底层依赖时，应先检查通用接口是否遗漏调用者真正需要的核心原语。

修订根 `SKILL.md`：

- 性能主路由增加硬进入条件：明确目标以及运行证据；
- 重要性路由明确覆盖“以未经测量的性能理由要求穿透底层对象”；
- 歧义规则规定先反查通用接口，只有接口无缺口且热点证据成立后才转入性能测量或受控逃逸。

新 agent 复测结果：

- R01 无性能证据：正确命中 `design-around-what-matters.md`；
- R02 声称需要底层一致性控制：正确先证明调用者独有语义并反查接口；
- R03 有明确 p99 与 68% 可重复热点：正确命中 `design-measured-critical-paths.md`。

该失败通过重做路由判据修复，没有修改题目来迁就技能。
