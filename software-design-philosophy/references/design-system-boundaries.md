# 系统边界与失败契约

用于跨进程协作、异步工作流、多份状态及恢复责任的设计。按当前关系读取相关段落，不把它当部署或组件选型手册。

每个结构建议说明：**真实压力与工作流、必须守住的契约、状态/规则所有者、结构动作、新增失败与成本、更简单候选、验证或撤回条件**。压力可以是性能，也可以是外部配额、离线能力、独立发布或隔离要求；不能仅从“读多、数据大、要高可用”推导组件。

## 逻辑边界与物理边界

按知识划分模块后，再判断是否需要独立进程或服务。比较同进程模块、按角色启动的同一制品与独立部署：自治收益能否支付通信、序列化、版本和恢复成本？共同内存状态、本地事务、低延迟和大中间数据都可能支持共置。

流水线只在阶段分别拥有转换知识时有用；管线负责顺序、取消、背压和中间产物生命周期。阶段按时间拆开却重复解释同一格式时，应重新组合。

API 聚合的边界跟随规则所有者：共同业务拼装可以由领域能力隐藏，客户端展示差异可以留给 BFF。比较直连、集中聚合与领域自治时，检查调用往返、重复规则、中央变更等待和 schema 治理，不能把网关或联邦当终局。

## 异步任务与事件

先说明调用者需要即时结果还是可以等待、谁拥有工作流状态。异步受理接口应覆盖任务身份、幂等提交、状态查询/通知、取消、结果权限与保留期。

- 受理与调度之间应有可靠交接：例如原子记录待调度状态，再由可重入调度器处理；返回“已受理”不能留下静默丢任务窗口。
- 区分受理、执行、结果可见和最终失败。进度表达真实阶段或完成量；总量未知就明确未知。
- 取消请求不等于已取消；取消与完成由唯一状态机裁决，终态不因迟到消息倒退。
- 工作队列适合分配可延后工作；可重放日志适合独立消费进度与重放。两者都需要容量上限、积压/过期、毒消息隔离和恢复责任，扩消费者不能绕过下游容量。
- 发布订阅减少发布者对消费者清单的依赖，但保留事件语义耦合。明确 schema 权威、兼容窗口、分区顺序、保留期、重复/迟到和重放副作用；同步不变量不能仅靠广播维护。

比较编排与协同时，演算新增一步、中途失败和恢复某个实例：流程规则应该集中还是由自治参与方分别拥有？一个本地事务足够时，不为未来拆服务预建 Saga；跨自治事务确需补偿时，要接受中间状态，并给出补偿失败、对账或人工恢复语义。补偿是新的操作，不等于撤销已经发生的外部效果。

验证受理后未调度、worker 崩溃、重复提交、取消竞态、离线后恢复和历史事件重放中实际相关的窗口。

## 外部副作用与结果未知

消息平台的交付保证不自动覆盖第三方业务效果。对可重试的外部写入，持久记录稳定业务操作 ID、同一幂等键、请求摘要及状态，再发起调用；恢复时查询或以原身份重放，不生成新键盲重试。

区分确定成功、确定拒绝/未执行与未知结果。未知结果需要查询外部权威，无法判定时进入对账或人工处置。本地终态与待发布结果应可靠提交后再确认输入；结果可重复发布，消费方仍需幂等。重放窗口不可超过下游幂等记录有效期，无法证明时停止自动重试。

按风险检验四个崩溃窗口：外调前、外部已执行但响应未达、响应已达但本地未提交、本地提交后尚未发布/确认。检查最终效果、内部状态与外部权威能否收敛，不仅检查消息是否投递。

## 多份状态与一致性

先确定权威和写入规则，再决定副本或投影。多个物理表示可以共享同一规则来源；多个独立可写权威则需要显式协调。

| 结构候选 | 需要的压力或契约 | 容易遗漏的成本与反证 |
|---|---|---|
| 缓存/预计算 | 可验证复用，昂贵计算、配额、成本或离线需求；性能理由需基线和热点 | 谁填充/失效、最大陈旧度、并发 miss、冷启动和全失效时源站保护；离线副本还需冲突/同步，不能伪装成可随意丢弃缓存 |
| 读副本 | 读压力与允许陈旧的工作流 | 按业务新鲜度路由，写后读可回主库或等副本追平；复制延迟与回退负载不能藏在“所有 SELECT 走副本”之后 |
| 分片 | 单节点容量或隔离约束确实越界，更简单的查询/模型/资源调整不足 | 用真实键分布比较局部性、热点、跨片查询/事务、路由权威和重分片恢复；慢查询本身不证明需要分片 |
| CQRS/投影 | 读写形状确有差异 | 明确派生方向、落后检测与重建；不要求双数据库，也不自动需要事件溯源 |
| 事件溯源/CDC | 历史重放是核心能力，或遗留状态需渐进同步 | 事件溯源以业务事件为权威；CDC 的原状态库仍是权威。日志存在不证明它是事实源；历史 schema 与副作用重放须可控 |

一致性按工作流表达，例如写后可见、会话不倒退、最大陈旧度和失败时可接受的中间状态；“最终一致”不自动提供有界收敛。并发版本、租约或锁一旦要求调用者遵守，就属于接口契约；过期持有者需要被阻止继续写入。

验证失效、落后、冲突、回填与重建中的相关场景。没有收益的第二份状态可以撤销，不把缓存、分片或事件模式当成熟度等级。

## 故障、容量与交付责任

错误分类与重试预算以 [错误处理边界](reduce-exception-surface.md) 为准。在此追踪预算与故障是否跨边界放大：

- 队列有界且压力能传回生产者；资源池隔离要覆盖真实共享资源。熔断、降载和回退应保留可正确提供的能力，不能伪造成功。
- 副本可用性取决于故障域、共同数据库/身份/控制面、健康判定与切换，不由节点数直接换算。探测超时只是怀疑失效；切换还要保证写入所有权，阻止旧主继续写。
- API、worker、初始化与迁移仅在启动、权限、扩缩或故障责任不同且有收益时拆开；readiness 不应被无关可选依赖变成全局失败开关。
- 发布结构取决于新旧协议/schema 共存、容量、所需流量证据与撤回速度。影子流量应隔离真实副作用；应用版本回退不能替代数据恢复。
- 恢复时间与数据丢失容忍由任务决定，备份、故障转移和重建需要相应演练支持，拓扑名称不是保证。

选择能检验当前责任分配的局部故障或迁移演练，不默认建立整套 SRE、压测或发布平台。
