# 深模块与接口

用于设计公共能力、减少调用者胶水和约束扩展。目标是少量易懂原语覆盖重要的完整工作流，不是减少方法数或把所有责任合成一个类。

## 从完整工作流设计原语

从已存在或已承诺的调用者任务出发，覆盖常见路径、低频高后果路径及真实长尾。沿创建、使用、结果、失败与清理检查接口，避免前半段简单、后半段必须读取内部实现。

列出模块应该统一的知识与稳定不变量，例如身份、生命周期、权限、状态、错误和等待。按对象、范围或状态转换归约当前专用动作，而不是逐一复制按钮和业务页面。多个删除动作可以归为范围操作；一个通用操作若依赖模式字符串和大量开关，仍可能是浅接口。

逐个演算关键用例，观察调用者新增的循环、转换、配对方法、状态追踪和异常处理。必要时用一张 `用例/频率与影响/调用路径/额外知识/缺口归属` 表，不要求独立维护多本账。没有频率数据时使用明确的定性权重，不声称测得覆盖率。

## 让契约检验抽象

实现前尝试从调用者视角简短表达：操作含义、输入输出语义、成功保证、重要状态与副作用，以及相关的顺序、并发、持久化和失败约定。代码类型已清楚表达的内容不用重复写成注释。

如果必须描述内部对象装配或算法步骤才能安全调用，检查抽象是否把责任留错了位置；如果说明简短却省略所有权或提交语义，补全契约。实现中的新发现可以反过来修正抽象，不要求冻结设计或先写整套文档。

普通路径使用模块能可靠决定的默认值。只有调用者知道且影响正确性的选择必须显式表达，不能为了简单而静默猜测。返回类型与名称应让读者能辨别单位、状态和所有权。

## 未覆盖能力放在哪里

| 归属 | 依据 |
|---|---|
| 核心原语 | 多个调用者反复需要，属于模块知识，能消除重复胶水 |
| 上层组合 | 现有原语足够清楚，差异属于特定业务流程 |
| 专用实现/适配器 | 差异来自设备、供应商或不可改的外部协议，可在共同契约后隐藏 |
| 类型化高级入口 | 调用者掌握模块无法推断的重要选择，或某类对象具有专用能力 |

高级入口只开放必要选择，避免万能 options、裸内部对象图或逐字段 Getter/Setter。它可以增加专用动词，但应复用主体身份、生命周期、权限、错误和观测，产物能回到公共句柄与资源治理。

检查逃逸的频率、深度、影响范围和重新汇入能力。相同逃逸成为常见路径时，重评核心原语；独立业务组合无需强行收编。没有真实扩展者时，不预建完整插件平台。

性能专用接口按 [性能约束下的设计](design-measured-critical-paths.md) 判断。不要仅因暴露了必要的生命周期或布局语义就认定泄露，也不要用“更快”绕过核心不变量。

## 独立测试 / Agent 调试面

这是条件性能力，不是深模块的默认附带交付。普通接口设计不主动增加高权限入口，也不为它设置确认步骤。用户已经要求时沿用该授权；只有正在设计此能力、却缺少允许的环境或动作范围时，才澄清缺失项。

此能力应通过稳定 CLI/API 使用，无需改业务代码；提供明确 schema、操作身份及幂等语义、限环境限能力的短期凭据、审计与资源自动回收。以独立部署或不可绕过的环境门禁保证生产不可达，不能成为普通生产身份能调用的隐藏后门或无类型 eval。验证未经授权的环境/身份确实被拒绝。

## 检验结果

只凭接口和契约演算关键工作流：普通调用者是否仍要重复内部规则，长尾是否有明确归属，重要选择是否被隐藏？薄适配器和纯函数无需为了“做深”扩充职责。若问题集中在错误传播，继续使用 [错误处理边界](reduce-exception-surface.md)。
