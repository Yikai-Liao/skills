# 深模块与接口

## 用完整工作流检验原语

以已有或已承诺的调用者任务检验创建、使用、结果、失败和清理，包括低频高后果路径与真实长尾。检查调用者仍需重复的循环、转换、配对操作、状态和恢复规则，不用方法少证明模块深，也不用模式字符串和大量开关伪装通用能力。

按共同对象、范围或状态转换组织原语，而不是逐个复制页面动作。

实现前尝试从调用者视角简短表达成功、状态、所有权、副作用及相关并发、持久化和失败契约。必须讲内部装配才能安全调用，可能是责任放错；说明短却漏掉提交语义，也不算好抽象。实现发现可以修正契约，不要求先写整套文档。

验收来自用户目标、领域不变量、既有公共行为或可信参照，不能只从新实现反推，更不能为通过检查放宽契约。复杂转换可用人工可核对的小例子；类型已表达的内容不重复注释。

## 给缺口确定归属

| 缺口 | 归属 |
|---|---|
| 多个调用者重复需要，属于模块知识 | 核心原语 |
| 原语已足够，差异属于具体业务 | 上层组合 |
| 设备、供应商或外部协议差异 | 共同契约后的专用实现或适配器 |
| 调用者独有的重要选择或对象专用能力 | 窄的类型化高级入口 |

普通路径使用模块能可靠决定的默认值，不猜测只有调用者知道的正确性选择。高级入口复用公共身份、生命周期、权限、错误与观测，产物能回到公共句柄和资源治理；不开放万能 options 或整个内部对象图。

同一逃逸反复成为常见路径时，重评核心原语；独立业务组合不强行收编，没有真实扩展者不预建插件平台。必要的布局或生命周期语义不自动算泄露，性能入口见[性能约束下的设计](design-measured-critical-paths.md)。

## 独立测试 / Agent 调试面

简单小工具、小程序不专门考虑独立调试面；复杂度上来，例如多状态、多组件协作或难复现工作流时，应询问用户是否考虑独立测试 / Agent 调试能力。询问不等于获准创建，也不阻止先交付不受该选择影响的设计。已有授权不重复询问；实际设计时缺少允许的环境或动作范围，才补足该项。

通过稳定 CLI/API 使用，无需改业务代码；保留 schema、操作身份与幂等、限环境限能力的短期凭据、审计及自动回收。以独立部署或不可绕过的环境门禁保证生产不可达，并验证拒绝未授权环境/身份；不能成为生产隐藏后门或无类型 eval。

需反复重现的工作流提供可重复起点与必要状态观察，但初始化不能直接灌入终态代替验证。目标转换仍经真实公共操作检查，一张截图不证明完整工作流。
