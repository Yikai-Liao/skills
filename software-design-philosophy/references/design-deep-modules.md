# 深模块与接口

## 模块深度与内部组织

完整操作由一个边界对外负责，内部可按输入、输出与效果明确的阶段组织，即使阶段只调用一次。拆分保持不变量、事务、锁范围与资源生命周期，各阶段用清楚的契约协作。

## 用完整工作流检验原语

从真实用例检验创建到结果、失败和清理，包括相关长尾。新模块尚无调用代码时，可在脑中或短小草稿中试写调用方式。以调用者实际承担的配对、转换、顺序和收尾评价深度，计入中转记录与外部装配。

按共同对象、范围或状态转换组织原语，让有信息保证它的模块完成操作。有读写阶段约束时，收回必要汇合与失败清理，保证读者结束才写、写者结束才返回。

从调用者视角说清成功、所有权、副作用与失败边界，并随实现核对。准备、内部修改、提交和发布是不同保证；返回 Result 不证明回滚，丢弃整次尝试也不等于局部事务。接入项目已有的错误、取消、并行调度和可观测性约定，必要差异做窄适配。

改动后检验一次真实调用或维护任务：内部协议是否退出，规则和失败责任是否易定位？验收依据用户目标、不变量、既有承诺或独立参照；复杂转换可用人工可核对的小例子。

## 给缺口确定归属

| 缺口 | 归属 |
|---|---|
| 多个调用者重复需要，属于模块知识 | 核心原语 |
| 原语已足够，差异属于具体业务 | 上层组合 |
| 设备、供应商或外部协议差异 | 共同契约后的专用实现或适配器 |
| 调用者独有的重要选择或对象专用能力 | 窄的类型化高级入口 |

普通路径使用模块能可靠决定的默认值，调用者独有的选择通过窄的类型化入口表达。高级入口复用公共身份、生命周期、权限、错误与观测，产物能回到公共句柄和资源治理。

同一逃逸反复成为常见路径时重评核心原语；独立业务组合留在上层，扩展契约服务于真实扩展者。必要布局与生命周期语义见[性能约束下的设计](design-measured-critical-paths.md)。

## 独立测试 / Agent 调试面

个人偏好：简单程序沿用现有测试入口；复杂系统或难复现工作流，询问是否考虑独立测试 / Agent 调试面，已有决定直接沿用。

接口用类型化 schema 表达操作，可重试操作明确身份与幂等。跨环境或具备特权能力的调试面，采用限环境限能力的短期凭据、审计及自动回收；用独立部署或环境门禁保证生产不可达，检验拒绝路径。

提供可重复起点与必要状态观察，目标转换经过真实公共操作检查。
