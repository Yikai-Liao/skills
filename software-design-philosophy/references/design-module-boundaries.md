# 模块与知识边界

## 从语义与知识开始

沿真实用例辨认数据单位、基数和时间关系：同一身份可有多个历史实例，当前值、快照和派生量不因共享 key 就是同一事实。新建与重构都据此决定类型和边界。

沿代表性修改追踪须共同解释的规则，优先高频或高后果任务，不用请求热度代替变更权重。相似代码可有独立语义；同源生成物和只读投影不自动构成多个权威。

权威交给有信息维护不变量的一方，明确状态的产生、修改、移交、失效与释放。新增派生状态或删状态、参数前，核对合法调用与状态变化中的可推导性及成本；初始化可推导不等于运行期可推导。必要缓存和快照可以保留。

反复误改须区分知识不可达、契约不足、实现错误与验证遗漏，不一律追加模块、上下文或流程。根因明确时不重做全系统诊断。

## 选择边界

- **合并**：同一规则或状态机总需共同理解、修改，合并能消除中间表示或重复恢复；同时检查是否引入无关依赖、共同发布或权限扩大。
- **拆分**：责任有独立变化原因，拆后可以独立理解；计入新接口、状态传递、导航与协调成本，不按执行顺序、组织图或每个用例自动建模块。
- **保留**：薄边界确实翻译外部协议、隔离信任或故障、保护稳定契约，不因“浅”而强行增加职责。

用命名记录表达共同成立的字段关系，变体表达真实互斥选择，各支只承担必要数据与处理。标准容器或迭代器满足消费契约时直接使用，核对顺序、重复项与边界语义。按真实增长上限和生命周期选表示，不凭少量例子假定固定容量，也不为有限结构预建递归框架。

模块可可靠决定的选项收回内部，调用者独有的选择留在契约。跨组织规则无法收进一处时，保留版本化契约与兼容责任。

个人取舍：**不采用多基类实现继承**。插件优先组合、接口、trait 或 concept；仅在契约稳定且子类不依赖父类内部状态及调用顺序时考虑单继承。

源码边界不自动成为服务边界；只有独立发布、容量、信任或故障收益足以支付通信和恢复成本时才拆进程。

## 检验实际收益

走通代表性调用或重放原任务，看权威是否收拢、必要适配是否留在边缘、调用者是否少学内部知识。领域概念的价值由真实用例与不变量决定。

类型、schema、可见性或现有检查保护可表达的不变量；就近说明不可推导的理由与兼容承诺，仓库指导链接权威内容。

入口应能引向真实修改点和有效验证；调用者仍靠提示词补做事务、清理或顺序步骤时，重评接口责任。
