# 错误处理边界

错误也是接口。减少的是调用者必须处理的状态与位置，不是诊断信息或重要的失败语义。

对当前工作流标出失败条件、结果是否确定、谁掌握恢复所需信息。按语义选择处理方式，不要求所有错误走相同流程：

| 方式 | 适用条件 | 不能牺牲的语义 |
|---|---|---|
| 定义消除边界错误 | 用户意图允许稳定的正常结果，如“确保对象不存在” | 不能把权限拒绝、损坏或未持久化伪装成成功 |
| 就地恢复 | 本层拥有充分信息，恢复不会重复危险副作用 | 有限预算、幂等依据、取消和可观测性 |
| 边界聚合 | 多种内部失败对调用者有相同处理方式 | 保留原因与追踪信息，不只换字符串逐层重抛 |
| 显式上报 | 调用者拥有事务、业务容忍度或策略信息 | 稳定且可区分的结果，让正确的人做决定 |
| 终止最小故障域 | 不变量已破坏，继续执行不安全 | 先判断状态持久性、隔离和恢复能力，不照搬进程中止 |

超时只说明停止等待，远端可能已完成。区分永久拒绝、暂态失败、过载和结果未知；未知结果不能直接当作普通失败后重新创建操作。

重试由一个主要责任方管理端到端 deadline、次数/时间上限和退避抖动；各层独立重试会乘法放大负载。过载需要限流、背压或拒绝，不能靠增加重试恢复。幂等与副作用边界不明确时，保留未知状态并查询/对账，不自动重试或吞错。外部副作用的具体协议见 [系统边界与失败契约](design-system-boundaries.md)。

用相关失败场景检验决定：正常边界、暂态恢复、预算耗尽、永久失败和结果未知是否到达正确责任方。删除已被新语义覆盖的重复预检查与 catch；只对本次改变的高风险失败路径做必要测试或故障注入。
