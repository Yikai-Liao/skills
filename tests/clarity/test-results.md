## 会话输出与设计讨论合并

本轮将解释、答疑、进展和调研汇报明确纳入触发范围，同时保留持久化文本与代码表达。主文件强调从读者已知的内容接续，文本参考增加会话回复与理解顺序的指导；短句、摘要和分层本身不作为理解改善的证明。

原独立设计技能合并为 `references/design-discussion.md`。保留提案、决定、现状更新、实施交接、偏移处理、条件决定与未完成工作；普通回复或润色不自动进入这些方法。独立技能入口和元数据移除，来源归入维护说明。

- 原有 108 个用例内容保留；迁入 19 个设计用例，其中纯起草与润色改为触发表达指导，仍不启动设计流程。
- 新增 11 个用例，覆盖会话触发、保存文本时补齐背景、句间关系、熟悉例子、必要信息就近可见、局部追问、阅读困难反馈和设计讨论中的 C4 使用。
- C4 完整方法与原有案例保留，并在触发描述、主文件、代理提示和设计讨论中明确入口。系统上下文、容器、组件与代码层次，以及动态、部署视图均保留。
- 静态检查通过：frontmatter 与代理 YAML、138 个用例的唯一 ID 和字段、13 份 Markdown 的 50 个本地链接及标题锚点、代码围栏、行尾空白与 `git diff --check`。迁入前逐项比对 19 个原设计用例，仅调整了上述两项触发类型；独立技能文件已移除。

作者自查核对了普通输出与设计讨论的分支、C4 入口及方法保留，以及原先纯表达边界与新增设计协作范围的衔接。历史结果不代表合并版本的行为结果。

尚未进行独立模型试跑或真人阅读评估。文件场景须检查实际读写结果；阅读成本和感受需要真实反馈，不能用字数或结构校验代替。

## 历史防御性表达调整

本轮逐项核对主文件、七份参考、代理提示与全部测试预期，同时检查维护说明和来源记录。检查包含两个独立问题：规则之间是否要求相反动作，以及规则产出的文字是否直接、有用。
