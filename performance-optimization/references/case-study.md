# 一次缓存与 SIMD 优化的取舍

此例来自 FluidSynth sinc 插值优化，说明接受与拒绝的依据；数值、工具和实现选择不是其他项目的默认要求。

## 消除重复计算，再看更细的瓶颈

原实现逐输出生成并归一化窗函数系数。按相位预计算归一化系数，运行时插值相邻行，消除了大量重复工作。随后从实际汇编发现样本解码未有效向量化，连续窗口表达改善了编译结果；普通可选 SIMD reduction 进一步优化点积。

交付目标是默认 SSE。native 构建用于判断 SIMD 潜力，但同时引入宽向量和 FMA，不能把全部差值当作向量宽度收益，也不能把诊断 flags 带入最终源码提速。

## 平均改善没有通过局部门禁

相邻输出复用已解码样本，完整 MIDI 比已有优化版本再快约 3–9%；部分短循环却回退 17–26%。局部结果使候选失去接受资格，不能拿完整曲目平均收益覆盖。

把缓存限定为完整安全块、其余执行原 fallback 的修复，仍未通过预先声明的逐路径门禁。最终撤回缓存，保留更简单的实现。这里的结论是这些缓存实现不满足本轮约束；并未证明解码复用在所有平台都无价值。

## 内层 SIMD 成功，整条路径仍可能失败

输出并行原型尝试让各 lane 处理不同输出。动态相位导致系数与输入需要重新组织；完整打包版本的系数生产和消费已经 SIMD，PCM 生产仍标量，转置产生 scratch 读写或 spill，完整调用反而更慢。

这区分了“预期消费循环已向量化”和“完整成本有净收益”。纯寄存器 tile 未被这些原型覆盖，不能一并宣判失败；若要继续，需要新的剖析依据及维护成本判断。

## 覆盖率和调用链决定是否继续

精确重复相位有机会复用最终系数，但真实 MIDI 的整数及短周期相位覆盖为零，因此本轮没有添加这条特化。外部请求从 64 增至 1024/4096 帧，内部插值仍以 64 帧执行；公共调用成本摊薄，不代表 sinc 内核块变大。

## 两次复核纠正了报告

两对计时时，速度比的中位数与耗时比中位数的倒数不同，报告必须与实际计算一致。三张函数内 static 表在 .bss 中已预留，按档位延迟的是初始化与触页，不能写成按需动态分配。

最终回到已测源码树后，核对树、冻结源文件、构建参数和 ELF 哈希，复用适用证据；没有伪称重新配对。质量验证同时保留既有 sinc4095 重建参照与独立有限核误差检查。

案例源于一次本地 FluidSynth 11/17/25-tap 优化实验；具体数字只说明当时的取舍，不是此 skill 的通用阈值。
