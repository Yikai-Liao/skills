# Classic principles and 2026 collaborative-development research

Date: 2026-09-08. Baseline `35f754a`; test set 0.7.0 at the time. Condensed on 2026-11-11; the full report, including per-source verification notes and retrieval method, is in Git history.

## Conclusion

The skill's spine (information hiding, deep modules, real change, failure contracts) still fits. Worth adding: identifying actual consumer dependencies, constraining generated implementations with checkable contracts, placing knowledge at its authority, splitting parallel work along shared contracts, and confirming that verification covers the final composition's real behavior. These went into the existing references; AI is the skill's user, so no separate "when used by AI" branch was added. Not an exhaustive literature review and no cross-model measurement.

## Classic sources

- [Hyrum's Law](https://www.hyrumslaw.com/): consumers come to depend on observable behavior never promised. Evolution now separates formal guarantees, observed dependencies, and unknowns, and samples consumers of the change. This does not freeze every detail or override a user's explicit direct cutover.
- [Test Doubles, *Software Engineering at Google* ch. 13](https://abseil.io/resources/swe-book/html/ch13.html): doubles have maintenance and fidelity costs. Seams go at genuinely uncontrollable or expensive dependencies; a database mock does not prove transactions or constraints.
- [Parallel Change](https://martinfowler.com/bliki/ParallelChange.html) and [End-to-End Arguments](https://web.mit.edu/Saltzer/www/publications/endtoend/endtoend.pdf): already covered by the evolution and system-contract rules; nothing added.

## arXiv evidence

Each paper was read at a pinned version. The evidence varies in strength and does not combine into a single speed-up figure.

| Paper | Finding | Limit |
|---|---|---|
| [Evaluating AGENTS.md, v2](https://arxiv.org/abs/2602.11988v2) | Generated context files raise cost without significantly changing the solve rate; gains from human-written files over none were not significant | Does not show AGENTS.md is harmful; mostly Python issue solving |
| [Probe-and-Refine Tuning, v2](https://arxiv.org/abs/2606.20512v2) | Guidance revised from synthetic fault probes: 33.0% vs 28.3% static vs 25.5% none (Qwen3.5-35B-A3B) | Longer guidance without length ablation; degrades across models |
| [Do Context Files Help Coding Agents?, v1](https://arxiv.org/abs/2607.27250v1) | No significant correctness gain from injected or retrieved context (17 tasks, 288 runs) | Small sample; not tested on GPT-5.6 |
| [Design Docs Are All You Need, v1](https://arxiv.org/abs/2609.05364v1) | Regenerated a library from design docs, aligning with worked small examples and a hand-checked reference model | Adopted the checkable examples and independent reference; "regeneration is cheaper" lacks an equal-budget maintenance comparison |
| [RefactorPlatform, v1](https://arxiv.org/abs/2609.04898v1) | A single agent with retrieval beat the multi-agent configurations tested | Success measured mainly by AST checks, which do not prove behavioral equivalence; single run |

Shared lesson: **first identify what is missing**. Supply authoritative knowledge when facts are missing; fix the interface, implementation, or verification when facts were found but the implementation is wrong. No single optimal document length follows from this research.

## Collaboration, verification, efficiency

- [Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): a completion claim does not replace the actual state. Anchor acceptance in user goals, domain invariants, and real artifacts; calibrate fallible verifiers against known failures rather than adding evaluators.
- [Building a C compiler with parallel Claudes](https://www.anthropic.com/engineering/building-c-compiler): agents chasing the same failure overwrote each other until work was split along independently checkable boundaries. Supports dividing work by dependency and acceptance boundaries and checking composition failures; not a fixed team size.
- [Harness design for long-running apps](https://www.anthropic.com/engineering/harness-design-long-running-apps): orchestration was removed after model upgrades; evaluators may still be lenient. The skill keeps acceptance responsibility and leaves orchestration to the task.
- [METR uplift update](https://metr.org/blog/2026-02-24-uplift-update/): efficiency estimates are hard to interpret. Maintenance evaluations should record rework, human effort, end-to-end time, and cost under quality constraints, not lines generated or tokens.

## Applied and rejected

Applied to the entry (hand-off baselines, stopping after required checks pass), module boundaries (unreachable knowledge versus implementation errors under a known contract), deep modules (independent acceptance evidence, checkable small examples, starting scenarios versus real workflows), evolution (implicit compatibility surface, double fidelity, collaborative write ownership, final composition), and audit (whether implementers can find the effective contract).

Rejected: TDD-generated architecture by default, unjustified whole-repo regeneration, permanent compatibility with every implicit behavior, a debugging entry for every design, AI-orchestration references, model-name branches, fixed approval or role counts.

## Maintaining the skill

Following [Build skills](https://learn.chatgpt.com/docs/build-skills) and [Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills): a model upgrade or real misuse can trigger a targeted evaluation that keeps the same tasks, counterexamples, constraints, tools, and budget, records model and skill version, and adds or removes instruction groups to compare behavior and cost. One success supports only that result. A clear failure may be fixed locally first without making a full controlled experiment a prerequisite.
